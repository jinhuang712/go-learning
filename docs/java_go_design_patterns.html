Java / Go 设计模式对照

本文目标 对比常用 GoF 设计模式在 Java 和 Go 中的不同实现方式,帮助 Java 开发者理解 Go 语言的设计哲学。
Go 的灵魂是:组合优于继承 · 简单优于复杂 · 明确优于隐式。
许多模式在 Go 中其实只需要一个函数、一个接口、几行代码即可表达。

1. Singleton(单例模式)

Java 实现

public class Singleton {
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

Go 实现

package singleton

import "sync"

type Singleton struct{}

var (
    instance *Singleton
    once     sync.Once
)

func GetInstance() *Singleton {
    once.Do(func() {
        instance = &Singleton{}
    })
    return instance
}

只放过 1 个进入 init Once->>Init: 调用一次 Init-->>Once: 返回 Once-->>T1: 返回 Once-->>T2: 直接返回(不再执行 init)
图 2 · sync.Once 在并发首次调用时的内部时序
对比说明
  • Java: 需要双重检查锁 + volatile 保证可见性
  • Go: 使用 sync.Once,更简洁、更安全,而且初始化时的 panic 会让 Once 保持已完成状态,需注意业务侧防御

2. Factory(工厂模式)

Java 实现

public interface Shape {
    void draw();
}

public class Circle implements Shape {
    public void draw() { System.out.println("Circle"); }
}

public class Square implements Shape {
    public void draw() { System.out.println("Square"); }
}

public class ShapeFactory {
    public static Shape getShape(String type) {
        if ("circle".equals(type)) return new Circle();
        if ("square".equals(type)) return new Square();
        return null;
    }
}

Go 实现

package factory

type Shape interface {
    Draw()
}

type Circle struct{}
func (c *Circle) Draw() { println("Circle") }

type Square struct{}
func (s *Square) Draw() { println("Square") }

func NewShape(shapeType string) Shape {
    switch shapeType {
    case "circle":
        return &Circle{}
    case "square":
        return &Square{}
    default:
        return nil
    }
}
对比说明
  • 结构非常类似,都是通过接口实现多态(Go 隐式实现 vs Java 显式 implements)
  • Go 的构造函数通常命名为 NewXxx,这是社区约定俗成的规范
  • 错误处理:Go 推荐返回 (Shape, error) 而非 nil,让调用者明确处理

3. Strategy(策略模式)

Java 实现

public interface PaymentStrategy {
    void pay(int amount);
}

public class CreditCardPayment implements PaymentStrategy {
    public void pay(int amount) { /* ... */ }
}

public class ShoppingCart {
    private PaymentStrategy strategy;

    public void setStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;
    }
}

Go 实现 · 接口风格

package strategy

type PaymentStrategy interface {
    Pay(amount int)
}

type CreditCardPayment struct{}
func (c *CreditCardPayment) Pay(amount int) { /* ... */ }

type ShoppingCart struct {
    strategy PaymentStrategy
}

func (s *ShoppingCart) SetStrategy(strategy PaymentStrategy) {
    s.strategy = strategy
}

Go 的另一种方式 · 函数作为策略

type PaymentFunc func(amount int)

func CreditCardPay(amount int) { /* ... */ }

type ShoppingCart struct {
    payFunc PaymentFunc
}

func (s *ShoppingCart) SetPaymentFunc(f PaymentFunc) {
    s.payFunc = f
}

// 使用
cart.SetPaymentFunc(CreditCardPay)
cart.SetPaymentFunc(func(amount int) {
    fmt.Println("pay by wallet", amount)
})
对比说明
  • 经典实现非常类似
  • Go 把函数作为一等公民,小策略直接传函数,无需为每种策略写一个类型
  • 这正是 Go 在 HTTP / log / sort 标准库中无处不在的风格 (http.HandlerFunc, sort.Slice)

4. Observer(观察者模式)

Java 实现

import java.util.ArrayList;
import java.util.List;

public interface Observer {
    void update(String event);
}

public class Subject {
    private List observers = new ArrayList<>();

    public void register(Observer o) { observers.add(o); }
    public void notifyObservers(String event) {
        observers.forEach(o -> o.update(event));
    }
}

Go 实现 · 同步

package observer

type Observer interface {
    Update(event string)
}

type Subject struct {
    observers []Observer
}

func (s *Subject) Register(o Observer) {
    s.observers = append(s.observers, o)
}

func (s *Subject) NotifyObservers(event string) {
    for _, o := range s.observers {
        o.Update(event)
    }
}

Go 的另一种方式 · 用 Channel 异步

type Event struct {
    Type string
    Data interface{}
}

type Subject struct {
    observers []chan<- Event
}

func (s *Subject) Notify(event Event) {
    for _, ch := range s.observers {
        select {
        case ch <- event:
        default: // 非阻塞,避免慢消费者拖垮发布者
        }
    }
}

5. Decorator(装饰器模式)

Java 实现

public interface Coffee {
    double cost();
}

public class SimpleCoffee implements Coffee {
    public double cost() { return 5.0; }
}

public class MilkDecorator implements Coffee {
    private Coffee coffee;
    public MilkDecorator(Coffee coffee) { this.coffee = coffee; }
    public double cost() { return coffee.cost() + 1.5; }
}

Go 实现

package decorator

type Coffee interface {
    Cost() float64
}

type SimpleCoffee struct{}
func (s *SimpleCoffee) Cost() float64 { return 5.0 }

type MilkDecorator struct {
    coffee Coffee
}
func (m *MilkDecorator) Cost() float64 { return m.coffee.Cost() + 1.5 }

func WithMilk(c Coffee) Coffee {
    return &MilkDecorator{coffee: c}
}

Go 的另一种方式 · HTTP 风格的函数式装饰器(中间件)

type Handler func(req *Request) *Response

func WithLogging(next Handler) Handler {
    return func(req *Request) *Response {
        log.Println("in", req.URL)
        resp := next(req)
        log.Println("out", resp.Status)
        return resp
    }
}

func WithAuth(next Handler) Handler {
    return func(req *Request) *Response {
        if !authOK(req) {
            return &Response{Status: 401}
        }
        return next(req)
    }
}

// 链式装饰
handler := WithLogging(WithAuth(myHandler))
这就是 Gin / Echo / Chi 中间件的本质 装饰器在 Go 中已经从「模式」演化为「日常写法」。 net/http 的 Handler / HandlerFunc 接口让中间件可无限套娃。

8. 番外:Functional Options(Go 圈最常用的「替代 Builder」)

type Server struct {
    addr    string
    timeout time.Duration
    logger  *log.Logger
}

type Option func(*Server)

func WithTimeout(d time.Duration) Option {
    return func(s *Server) { s.timeout = d }
}

func WithLogger(l *log.Logger) Option {
    return func(s *Server) { s.logger = l }
}

func NewServer(addr string, opts ...Option) *Server {
    s := &Server{addr: addr, timeout: 10 * time.Second}
    for _, opt := range opts {
        opt(s)
    }
    return s
}

// 使用
srv := NewServer(":8080",
    WithTimeout(30*time.Second),
    WithLogger(myLogger),
)
为什么 Functional Options 胜过 Builder
  • 类型安全:不会出现 Builder 模式里「忘了调 build()」的运行期错误
  • 向前兼容:加新选项不破坏调用方代码
  • 零值友好:不调用任何 Option 时,Server 也是可用的
核心心智迁移
  • 抛弃继承思维,多用组合
  • 善用函数作为一等公民,小策略直接传函数
  • 遇到「需要广播 / 异步通知」的场景,优先考虑 Channel
  • 设计模式不是教条,Go 鼓励用最少的概念解决问题
