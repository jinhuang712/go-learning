3.1 Select 基础语法

select 是 Go 为多路 Channel I/O 量身打造的语句。它长得像 switch,但每个 case 不是布尔判断,而是一个具体的 Channel 操作(发送或接收)。Go 运行时会同时挂起到所有 case,只要有一个 ready 就触发它。

1. 基本语法

select {
case msg1 := <-ch1:
    // ch1 可读时执行
case msg2 := <-ch2:
    // ch2 可读时执行
case ch3 <- value:
    // ch3 可写时执行
default:
    // 上面都不就绪时立刻执行 (可选)
}
case 的本质 case 后面只能跟「Channel 接收 <-ch」或「Channel 发送 ch <- v」这两类 I/O 表达式;不能写普通比较或函数调用。 所以 select 只为 Channel 服务,不是通用控制流。

2. 三大核心语义

3. 完整代码示例

func DemoSelectBasics() {
    ch1 := make(chan string)
    ch2 := make(chan string)

    go func() {
        time.Sleep(100 * time.Millisecond)
        ch1 <- "来自 Channel 1"
    }()
    go func() {
        time.Sleep(150 * time.Millisecond)
        ch2 <- "来自 Channel 2"
    }()

    // 循环 2 次,把两条消息都接收掉
    for i := 0; i < 2; i++ {
        select {
        case msg1 := <-ch1:
            fmt.Println("收到:", msg1)
        case msg2 := <-ch2:
            fmt.Println("收到:", msg2)
        }
    }
}

因为 ch1 先 ready,第一轮取 ch1;第二轮 ch2 也 ready 了,取 ch2。但顺序不保证: 如果你把两个 sleep 调成一样,Go 运行时会随机选一个。

坑点:不要依赖 case 书写顺序 Go spec 明确写: "if multiple are ready, one is chosen via a uniform pseudo-random selection"。 所以下面这种「优先级写法」完全无效: 
select {
case x := <-highPriority: ... // 多 case 同时 ready 时不会优先!
case x := <-lowPriority:  ...
}
若需优先级,要写嵌套 select 或先单独 try-recv 高优先级再 fallback。

4. 多 case 同时就绪 → 伪随机

这个特性常被新手忽略,但是负载均衡的天然来源。例如 Fan-in 合并多个生产者时,即使所有源都在持续推消息,select 也会均匀地从每个源取,不会饥饿某一路。

// 两路同时一直有数据时,大量循环后近似 50/50 各取一半
for i := 0; i < 1000; i++ {
    select {
    case <-chA: // 永远都 ready
    case <-chB: // 永远都 ready
    }
}

5. 空 select 的死锁与活用

select {} // 永久阻塞,goroutine 永远 park 在这里
  • 陷阱: 如果 main goroutine 走到这里,整个程序卡住,Go 运行时会检测到「所有 goroutine 都在睡」并 panic fatal error: all goroutines are asleep - deadlock!
  • 正确用法: 有其他 goroutine 在后台运行(如 HTTP server),用 select{} 让 main 不退出。

6. 生产环境坑点

  • 空 select 用错地方 → fatal deadlock。
  • 无 default 的 select 写在循环里阻塞 → 整个 goroutine hang 住,内存泄漏。
  • 读到 nil channel → case <-nilCh永远不会 ready,常用于「动态关闭某一路监听」。但不小心把所有 case 都置 nil → 也变成 select{} 死锁。
  • case 顺序不是优先级 → 想要优先级必须显式分层 select。
小技巧 · 用 nil channel 关闭某一路 把 chA = nil 后,case x := <-chA 永远不被选中,等于动态屏蔽这一路。 可用于「输入流读完后只继续监听另一路」。

📝 练习题

  1. 启动两个 goroutine,分别每 100ms 往 chA / chB 推一条消息,主 goroutine 用单个 for-select 接收 10 秒,统计 chA / chB 各被选中的次数,验证近似均匀。
  2. 实现一个真正的「优先级 select」: highPri 比 lowPri 优先,只有 highPri 没数据时才取 lowPri。(提示: 嵌套 select + default)
  3. 写一段代码,在某个时刻把一个 channel 变量改写为 nil,观察 select 行为变化。
