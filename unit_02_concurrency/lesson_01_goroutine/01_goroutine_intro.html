1.1 Goroutine 基础与底层原理

1.1 什么是 Goroutine

Goroutine 是 Go 语言中轻量级的并发执行单元,由 Go 运行时(runtime)在用户态调度,而非由操作系统内核调度。它不是线程,但行为上可以当成「超便宜的线程」来使用。

启动一个 Goroutine 极其简单 — 只要在函数调用前加 go 关键字:

go func() {
    fmt.Println("Hello from goroutine!")
}()

1.4 必踩的第一坑:main 不等子 Goroutine

坑点 main() 函数本身也是一个 Goroutine。当 main 退出时,整个程序退出, 不会像 Java Thread.join() 那样默认等所有线程结束。

错误写法:忘记等待 Goroutine 完成

package main

import "fmt"

func main() {
    go func() {
        fmt.Println("Hello from goroutine!")
    }()
    // main 立即退出,子 Goroutine 可能根本来不及打印
}

正确写法:使用 WaitGroup 等待

package main

import (
    "fmt"
    "sync"
)

func main() {
    var wg sync.WaitGroup
    wg.Add(1)

    go func() {
        defer wg.Done()
        fmt.Println("Hello from goroutine!")
    }()

    wg.Wait() // 等待 Goroutine 完成
}
Java 对照 sync.WaitGroup 等价于 Java 的 CountDownLatch: Add(n) 对应 new CountDownLatch(n), Done() 对应 countDown(), Wait() 对应 await()。 只是 Go 用了 defer wg.Done() 这种更安全的成对模式。

1.5 生产环境坑点

坑点 1:Goroutine 泄露 Goroutine 因为等待 Channel、锁等永远阻塞,就会泄露。Go 的 GC 只回收对象内存, 不会回收阻塞的 Goroutine。详见 1.3 Goroutine 泄露。
坑点 2:过度使用 Goroutine 虽然 Goroutine 轻量,但并不是越多越好。过多会增加调度开销、GC 压力和内存占用。 处理 100 万任务时,启动 100 万个 Goroutine 是反模式 — 应该用 Worker Pool 或信号量 Channel 限制并发。
坑点 3:循环变量捕获(Go < 1.22) 在 Go 1.22 之前,for i := range 循环里所有 Goroutine 共享同一个 i, 最终都会打印同一个值。Go 1.22 已修复 (loopvar 改为每轮新建),但生产仍可能跑在老版本。 
// 错误写法(Go < 1.22):所有 Goroutine 共享同一个 i
for i := 0; i < 10; i++ {
    go func() {
        fmt.Println(i) // 极可能全部打印 10
    }()
}

// 正确写法 1:用参数传递
for i := 0; i < 10; i++ {
    go func(i int) {
        fmt.Println(i)
    }(i)
}

// 正确写法 2:在循环内重新声明同名变量
for i := 0; i < 10; i++ {
    i := i
    go func() {
        fmt.Println(i)
    }()
}
