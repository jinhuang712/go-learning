2.1 Channel 基础

1.1 什么是 Channel

Channel 是 Go 用于 Goroutine 间通信和同步的核心原语, 是 CSP (Communicating Sequential Processes) 并发模型的语言级实现。

CSP 核心思想 「不要通过共享内存来通信,而要通过通信来共享内存」 — Rob Pike。 Java 的世界:多线程操作同一块内存,用 synchronized / Lock 保护。 Go 的世界:每个 Goroutine 持有自己的状态,通过 channel 把数据交给下一个 Goroutine。

1.2 Channel 的两种类型

类型语法行为
无缓冲 Channelmake(chan T)send 和 recv 必须同时就绪,否则阻塞 — 强同步 handoff
有缓冲 Channelmake(chan T, n)缓冲未满时 send 不阻塞;缓冲非空时 recv 不阻塞

1.3 基本操作

ch := make(chan int)

// 发送
ch <- 42

// 接收
val := <-ch

// comma-ok 检查 channel 是否已关闭
val, ok := <-ch
if !ok {
    fmt.Println("channel 已关闭,收到的是零值")
}

// 关闭(只能由 sender 关闭,不能 close 已 nil 的 channel,
// 也不能 close 两次,否则 panic)
close(ch)

// 用 range 遍历直到关闭
for v := range ch {
    fmt.Println(v)
}

1.4 必看图: 无缓冲 channel 的同步 handoff

sequenceDiagram participant G1 as Sender goroutine participant Ch as ch (unbuffered) participant G2 as Receiver goroutine Note over G1,G2: 场景 1 — sender 先到 G1->>Ch: ch <- 42 Note over G1,Ch: G1 阻塞,挂到 ch.sendq G2->>Ch: v := <-ch Ch-->>G2: 直接拷贝 42 → v Ch-->>G1: 唤醒 G1 继续 Note over G1,G2: 两端继续执行 Note over G1,G2: 场景 2 — receiver 先到 G2->>Ch: v := <-ch Note over G2,Ch: G2 阻塞,挂到 ch.recvq G1->>Ch: ch <- 42 Ch-->>G2: 直接拷贝 42 → v(不进缓冲) Ch-->>G1: 唤醒 G1 继续
图 · 无缓冲 channel 是同步 rendezvous:谁先到谁阻塞,数据在二者之间直接拷贝,根本不经过缓冲区。

1.5 Java 对照

特性JavaGo

无缓冲SynchronousQueuemake(chan T)

代码对照

Java (SynchronousQueue 等价于无缓冲 Channel):

import java.util.concurrent.BlockingQueue;
import java.util.concurrent.SynchronousQueue;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        BlockingQueue<Integer> queue = new SynchronousQueue<>();

        new Thread(() -> {
            try {
                System.out.println("Thread: 发送数据 42");
                queue.put(42);
                System.out.println("Thread: 发送完成");
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }).start();

        System.out.println("Main: 等待接收...");
        Integer val = queue.take();
        System.out.println("Main: 接收到 " + val);
    }
}

Go (无缓冲 Channel):

package main

import "fmt"

func main() {
    ch := make(chan int)

    go func() {
        fmt.Println("Goroutine: 发送数据 42")
        ch <- 42
        fmt.Println("Goroutine: 发送完成")
    }()

    fmt.Println("Main: 等待接收...")
    val := <-ch
    fmt.Printf("Main: 接收到 %d\n", val)
}
心智迁移要点
  • Java: 共享内存是默认方式,队列只是辅助工具
  • Go: Channel 是并发通信的核心方式,优先考虑 Channel
  • Java: InterruptedException 必须捕获或上抛
  • Go: Channel 操作不会抛异常,阻塞是正常控制流(不是异常)

1.6 关闭语义与 comma-ok 惯用法

错误写法:从已关闭 channel 接收,收到零值还以为是正常数据

ch := make(chan int)
close(ch)
val := <-ch // 不 panic,收到 int 零值 0
fmt.Println(val) // 输出 0 — 但你以为 sender 真的发了 0?

正确写法:comma-ok 检查关闭

ch := make(chan int, 1)
ch <- 42
close(ch)

val, ok := <-ch
if ok {
    fmt.Println("接收到:", val) // 42, ok=true
}

val, ok = <-ch
if !ok {
    fmt.Println("Channel 已关闭,收到零值") // ok=false
}

// 或用 range 自动处理关闭
ch2 := make(chan int, 3)
ch2 <- 1; ch2 <- 2; ch2 <- 3
close(ch2)
for v := range ch2 {
    fmt.Println("遍历收到:", v)
}

1.7 无缓冲 vs 有缓冲

// 无缓冲 Channel — 必须 sender + receiver 同时就绪
unbuffered := make(chan int)
go func() {
    unbuffered <- 1  // 阻塞,直到 main 来 <-unbuffered
}()

// 有缓冲 Channel — 缓冲区满之前 send 不阻塞
buffered := make(chan int, 2)
buffered <- 1  // 立即返回
buffered <- 2  // 立即返回
// buffered <- 3  // 这一行会阻塞,缓冲区已满

1.8 生产坑点

坑点 1: 向已关闭的 channel 发送会 panic 
ch := make(chan int)
close(ch)
ch <- 1 // panic: send on closed channel
坑点 2: 关闭 channel 多次会 panic 
ch := make(chan int)
close(ch)
close(ch) // panic: close of closed channel
坑点 3: 忘记 close 导致 range 永远阻塞 详见 1.3 Goroutine 泄露。
坑点 4: nil channel 永远阻塞 
var ch chan int  // nil channel
ch <- 1          // 永远阻塞!不 panic
<-ch             // 永远阻塞!不 panic

// 但这正是 select 中「禁用某个 case」的常用技巧 — 见 L3.3
