4.2 Context 树结构与级联取消

Context 在内存里是一棵真正的树。每次调用 WithCancel / WithTimeout / WithValue,Go 都会: 新建一个子节点,把它「挂」到父节点的「子链表」里,然后返回这个子节点。 一旦父节点被取消,Go 会沿着子链表递归地把所有后代标记为 Done。

1. 树的根:Background 与 TODO

  • context.Background():所有树的根。用于 main 函数、init、最外层入口。永远不会被取消、没有超时、没有 value。
  • context.TODO():语义上的「占位」。功能上和 Background 完全相同,只是表达「这里以后应该传一个真正的 Context,目前还没想好」。go vet 和 IDE 会把它识别为「待修复」。

2. 四种派生函数

函数派生方式典型用途Java 类比
WithCancel(parent)返回子 ctx + cancel 函数用户取消、graceful shutdownFuture.cancel(true)
WithTimeout(parent, d)子 ctx 在 d 后自动取消RPC / 数据库调用超时future.get(d, unit)
WithDeadline(parent, t)子 ctx 在绝对时刻 t 后自动取消整条请求的最后期限调度器 deadline
WithValue(parent, k, v)子 ctx 多挂一个 KVtraceID / userID 元数据MDC.put()

两条单向规则
  • 父 cancel → 所有子孙 cancel(向下广播,递归到所有 Leaf)
  • 子 cancel → 父不受影响(单向,父 ctx 继续有效)

4. 实现机制:为什么是「树」?

当你写 ctx2, cancel := context.WithCancel(ctx1),Go 内部做了三件事:

  1. 构造一个 cancelCtx 结构体,记录 parent = ctx1。
  2. 把这个新节点注册到 ctx1 的 children map 里。
  3. 启动一个监听 goroutine(仅当 parent 不是 cancelCtx 时)等待父级 Done。

当 cancel() 被调用,流程是:

  1. 关闭自己的 done channel(让所有 <-ctx.Done() 解除阻塞)。
  2. 遍历自己的 children,递归调用每个孩子的 cancel()。
  3. 把自己从 parent 的 children 中移除(避免父节点的 cancel 时重复关闭)。

5. 最佳实践清单

7 条铁律
  1. Context 永远是函数第一个参数,命名 ctx,类型 context.Context。
  2. 用 context.Background() 作为顶层入口(main / HTTP handler / consumer loop)。
  3. 不确定时用 context.TODO(),绝不要传 nil。
  4. WithCancel / WithTimeout 返回的 cancel必须 defer cancel(),即使你已经触发过 cancel。
  5. WithValue 只用于跨中间件传递元数据(traceID, userID),不要传业务参数。
  6. WithValue 的 key 必须用自定义类型,避免跨 package 冲突。
  7. 不要把 Context 放进 struct 字段(除非你的 struct 本身就是「请求范围」对象,如 RequestScope)。

6. Java 对照:InterruptibleFuture 的痛点

为什么 Java 没有 Context

Java 想做「带超时的 RPC 调用」,通常长这样:

ExecutorService exec = Executors.newCachedThreadPool();
Future<Result> f1 = exec.submit(() -> callDB());
Future<Result> f2 = exec.submit(() -> callRedis());
try {
    Result r = f1.get(200, TimeUnit.MILLISECONDS);
} catch (TimeoutException e) {
    f1.cancel(true);   // 1. 中断标记
    f2.cancel(true);   // 2. 还要手动 cancel 其他兄弟
}

问题:

  • 每个 Future 都要显式 cancel,容易漏写。
  • cancel(true) 只是设置中断标记,被调用方必须主动 check Thread.interrupted(),如果不写就无效。
  • 请求元数据(traceID)走 ThreadLocal,异步任务里会丢。

Go 用一个 ctx 参数把三件事统一:取消信号 + 截止时间 + 元数据,并自动递归广播给所有后代。一次定义,处处生效。

7. 可运行示例:cancel 级联

func main() {
    root := context.Background()
    ctxA, cancelA := context.WithCancel(root)
    ctxB, cancelB := context.WithTimeout(ctxA, 1*time.Second)
    defer cancelB()

    go func() {
        <-ctxB.Done()
        fmt.Println("B 收到:", ctxB.Err()) // → context canceled
    }()

    // 取消 A,B 也会立刻被取消(级联)
    cancelA()
    time.Sleep(50 * time.Millisecond)
}

📝 练习题

  1. 构造一个三层 ctx 树:root → WithTimeout(1s) → WithCancel。在第三层 ctx 上启动一个 goroutine 等 ctx.Done();然后只 cancel 第二层,看第三层是否也被取消。
  2. 实现一个 FanOut(ctx, []func(ctx)):并发执行所有任务,只要任何一个出错就 cancel 整体 ctx,其他任务立即退出。
  3. 把 WithValue 用错一次:用 string 当 key,在两个 package 里用同一个 "id",观察读到的值。再改成自定义 type 修复。
