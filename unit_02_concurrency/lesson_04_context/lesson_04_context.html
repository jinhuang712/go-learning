Lesson 4 · Context 传递与级联取消

本课进入 Go 服务端开发最重要的工具:context.Context。它是请求链路中传递「取消信号、超时、截止时间、元数据」的统一语言。 一旦你写过 Go 微服务,几乎每一个函数签名都会以 ctx context.Context 开头——这不是约定,是 Go 团队官方推荐。

为什么 Context 是 Go 的「神器」 在 Java 里,「中断一个长时间任务」要靠 Thread.interrupt(); 「带超时调用」要靠 Future.get(timeout); 「在线程间传递请求上下文」要靠 ThreadLocal / MDC。 Go 把这三件事统一到一个接口 context.Context,可以跨 goroutine 边界传播,而且层层派生、级联取消。

go run .
go test ./unit_02_concurrency/lesson_04_context

🎯 本课核心收获

  • 理解 Context 树:任何子 Context 的取消都不会影响父级,但父级取消会级联取消所有后代。
  • 掌握 WithCancel / WithTimeout / WithDeadline / WithValue 四种派生方式的边界。
  • 记住三条铁律:ctx 永远是函数第一个参数、cancel 一定要 defer、不要把 ctx 放进 struct。
  • 对比 Java InterruptibleFuture / ThreadLocal 的痛点,理解为什么 Go 选择「显式传递」。
