Lesson 5 · Sync 包与 Atomic 原子操作

Go 推崇「Don't communicate by sharing memory; share memory by communicating」——但这不代表共享内存不能用。 当数据结构简单(单个计数器、状态标志、单例),用锁或原子操作往往比 channel 更直接、更快。本课系统梳理 sync 包和 sync/atomic 的核心原语。

🚀 运行方式

在 main.go 中调用 lesson_05_sync_atomic.Run() 即可执行本 Lesson 演示代码:

go run .
go test ./unit_02_concurrency/lesson_05_sync_atomic
go test -race ./unit_02_concurrency/lesson_05_sync_atomic   # 顺便验证无 race

🎯 本课核心收获

  • 掌握 Mutex 状态机:unlocked → locked → woken/starvation,了解 Go 1.9+ 的饥饿模式。
  • 理解 RWMutex 多读单写的语义:读读并行、写写互斥、读写互斥。
  • 清楚什么时候用锁,什么时候用 channel,什么时候用 atomic——三者并非替代关系。
  • 会用 go test -race 自我验证,而不是肉眼盯代码。
使用顺序建议 Go 团队推荐:能用 channel 解决的优先用 channel(语义清晰); channel 太重的简单计数 → 用 atomic(无锁,最快); 数据结构复杂或需要保护多个字段 → 用 Mutex / RWMutex。
