3.1 select 基础

select 长得像 switch,但骨子里完全不一样——它专门用来同时等待多个 channel 操作,哪个先就绪就跑哪一个。它是 Go 唯一能在语法层做多路复用的语句,所有「超时、退出、合并多个数据源」的模式都从它衍生。

1. select 语法

select {
case <-ch1:
    // 从 ch1 接收数据
case ch2 <- val:
    // 向 ch2 发送数据
case v, ok := <-ch3:
    // 带 comma-ok 的接收
default:
    // 所有 case 都阻塞时执行 (可选)
}

每个 case 必须是一个 channel 操作(send 或 recv),不能是任意表达式——这是和 switch 最大的区别。

2. 三条核心规则

  1. 有就绪 case → 选一个执行。多个同时就绪时伪随机挑一个,避免某条 channel「霸占」。
  2. 没有就绪 case + 有 default → 立刻跑 default,不阻塞(非阻塞 select 模式)。
  3. 没有就绪 case + 无 default → 当前 Goroutine 进入 Gwaiting,挂在所有 case 涉及的 channel 的等待队列上,直到任一就绪。

4. 为什么要随机选择?

如果多个 case 同时就绪,select 伪随机挑一个执行——这是刻意设计,不是 bug。原因有两个:

  • 避免饥饿:如果按代码书写顺序选,排在前面的 channel 永远优先,后面的可能永远轮不上。
  • 避免依赖顺序写代码:你不能假设「上面那行更优先」,这种隐式优先级会随重构而漂移。如果真需要优先级,自己用嵌套 select + default 实现。

Java NIO Selector 写法

import java.nio.channels.*;
import java.util.Iterator;

public class NioSelectorExample {
    public static void main(String[] args) throws Exception {
        Selector selector = Selector.open();

        SocketChannel ch1 = SocketChannel.open();
        ch1.configureBlocking(false);
        ch1.register(selector, SelectionKey.OP_READ);

        SocketChannel ch2 = SocketChannel.open();
        ch2.configureBlocking(false);
        ch2.register(selector, SelectionKey.OP_READ);

        while (true) {
            selector.select(); // 阻塞直到有事件
            Iterator<SelectionKey> keys = selector.selectedKeys().iterator();

            while (keys.hasNext()) {
                SelectionKey key = keys.next();
                if (key.isReadable()) {
                    // 处理可读事件
                }
                keys.remove();
            }
        }
    }
}

Go select 等价写法

package main

import (
    "fmt"
    "time"
)

func main() {
    ch1 := make(chan string)
    ch2 := make(chan string)

    go func() {
        time.Sleep(100 * time.Millisecond)
        ch1 <- "来自 Channel 1"
    }()

    go func() {
        time.Sleep(200 * time.Millisecond)
        ch2 <- "来自 Channel 2"
    }()

    for i := 0; i < 2; i++ {
        select {
        case msg1 := <-ch1:
            fmt.Println("收到:", msg1)
        case msg2 := <-ch2:
            fmt.Println("收到:", msg2)
        }
    }
}
心智迁移要点
  • Java 的 Selector 是类库,Go 的 select 是语法——后者使用门槛低、组合性强。
  • Java 事件按注册顺序处理,Go 多就绪 case 伪随机选,反而避免了饥饿。
  • Java NIO 主要服务网络编程,Go select 服务所有 channel 场景:超时、退出、fan-in 都靠它。

6. 可运行代码示例

错误写法: 忘记 select 也会阻塞

// 错误! 没有 default,且没人发送,会永远阻塞 (死锁)
ch := make(chan int)
select {
case <-ch:
    fmt.Println("收到数据")
}

正确写法 1: 使用 default 实现非阻塞

ch := make(chan int)
select {
case <-ch:
    fmt.Println("收到数据")
default:
    fmt.Println("没有数据就绪")
}

正确写法 2: 确保有 case 会就绪

ch := make(chan int, 1)
ch <- 42
select {
case val := <-ch:
    fmt.Println("收到:", val)
}

随机选择示例

package main

import (
    "fmt"
    "time"
)

func main() {
    ch1 := make(chan string)
    ch2 := make(chan string)

    // 两个 Goroutine 同时发送数据
    go func() {
        time.Sleep(50 * time.Millisecond)
        ch1 <- "A"
    }()

    go func() {
        time.Sleep(50 * time.Millisecond)
        ch2 <- "B"
    }()

    // 多次运行: A / B 的出现顺序随机
    for i := 0; i < 5; i++ {
        select {
        case msg := <-ch1:
            fmt.Println("第", i+1, "次:", msg)
        case msg := <-ch2:
            fmt.Println("第", i+1, "次:", msg)
        }
    }
}

7. 生产环境坑点

坑点 1: 所有 case 都阻塞导致死锁 
ch1 := make(chan int)
ch2 := make(chan int)
select {
case <-ch1:
case <-ch2:
}
// 两个 channel 都没人发送 → fatal error: all goroutines are asleep - deadlock!
只要 select 没有 default,且所有 case 都没机会就绪,就必死锁(单 G 程序里 runtime 会直接 panic)。
坑点 2: 忽略 nil channel 的特殊行为 
var ch chan int // nil channel
select {
case <-ch: // nil channel,这个 case 永远不会被选中
    fmt.Println("永远不会执行到这里")
default:
    fmt.Println("总是执行 default")
}
nil channel 在 select 中永远阻塞。这其实是一个很有用的特性——可以把变量设成 nil 来「临时禁用」某个 case,详见 3.3 节。
坑点 3: 循环里用 time.After 内存泄露 
// 错误: 每次循环都创建新 Timer,且不会被回收
for {
    select {
    case <-ch:
    case <-time.After(5 * time.Second):
    }
}

// 正确: 复用 Timer
timeout := time.NewTimer(5 * time.Second)
defer timeout.Stop()
for {
    select {
    case <-ch:
        if !timeout.Stop() { <-timeout.C }
        timeout.Reset(5 * time.Second)
    case <-timeout.C:
        return
    }
}
详细解释见 3.3 节坑点专项。
