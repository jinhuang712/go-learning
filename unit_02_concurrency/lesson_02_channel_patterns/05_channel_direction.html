2.5 Channel 方向约束

Channel 类型在 Go 里有三种方向标注,提供编译期的方向安全:

类型含义允许的操作
chan T双向send + recv + close
chan<- T只发送send + close
<-chan T只接收recv
记忆口诀:箭头指向 chan chan<- 箭头指向 chan(数据进 chan) = 只发送;
<-chan 箭头从 chan 出来 = 只接收。

1. 三种方向可视化

隐式转成 chan<- T 或 <-chan T,但反过来不行 (单向不能转回双向)
图 · chan / chan<- / <-chan 三种方向约束的语义和编译期检查

2. 为什么需要方向约束?

方向约束是 Go 提供的类型级别的契约。它能:

  • 防止误操作:函数声称只发送,就保证不会误读;反之亦然
  • 编译期检查:错误第一时间被发现,不是运行时 panic
  • API 表达更清晰:看函数签名就能猜出语义,无需翻文档

3. 三种典型用法

用法 1:函数参数约束职责

// producer 只能发送,编译保证不会 read 这个 channel
func producer(ch chan<- int) {
    for i := 0; i < 5; i++ {
        ch <- i
    }
    close(ch)
    // v := <-ch  // ❌ 编译错误:invalid operation: receive from send-only chan
}

// consumer 只能接收
func consumer(ch <-chan int) {
    for v := range ch {
        fmt.Println(v)
    }
    // ch <- 1  // ❌ 编译错误
    // close(ch)  // ❌ 编译错误
}

func main() {
    ch := make(chan int)  // 创建必须是双向 chan int
    go producer(ch)        // 隐式转换为 chan<- int
    consumer(ch)           // 隐式转换为 <-chan int
}

用法 2:工厂函数返回只读 channel

// 调用者拿到的 channel 不能误关闭 / 误发送
func numbers() <-chan int {
    ch := make(chan int)
    go func() {
        defer close(ch)
        for i := 0; i < 10; i++ {
            ch <- i
        }
    }()
    return ch  // 返回时双向 → 只读
}

func main() {
    for v := range numbers() {
        fmt.Println(v)
    }
}

用法 3:Pipeline 中明确每一段的方向

// stage1: 只输出
func gen(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for _, n := range nums { out <- n }
    }()
    return out
}

// stage2: 输入只读,输出只写——清晰表达数据流向
func sq(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for n := range in { out <- n * n }
    }()
    return out
}

func main() {
    for v := range sq(gen(2, 3, 4)) {  // pipeline
        fmt.Println(v)  // 4, 9, 16
    }
}

4. Java 视角对照

Java 没有方向约束 Java 的 BlockingQueue 接口同时提供 put 和 take,没办法在编译期限制某个方法只能用一边。 要做到类似效果,得用接口拆分 (如 Producer<T> / Consumer<T>) 然后强制类型转换——非常繁琐。 Go 的 chan<- / <-chan 是语言级别免费提供的契约。

6. 常见坑点

坑点 1:误以为单向 channel 能在函数内 close 
func consumer(ch <-chan int) {
    close(ch)  // ❌ invalid operation: cannot close receive-only channel
}
设计意图:接收方不应该关闭 channel,所以编译器禁止。
坑点 2:不能把单向 channel 转回双向 
var ro <-chan int = make(chan int)
var bi chan int = ro  // ❌ cannot use ro (variable of type <-chan int) as chan int
原因:类型系统单向收紧。要想再发送,必须保留双向引用。

📝 练习题

  1. 写一对函数 producer(out chan<- int) 和 consumer(in <-chan int),在 producer 里加一行 <-out 看编译报错。
  2. 用方向约束实现一个三段 pipeline:gen → sq → print,每段都用合适的方向类型。
  3. 写一个 tee(in <-chan int) (<-chan int, <-chan int) 函数,把一路输入复制成两路输出。
