2.1 Channel 基础语法

Channel 是 Go 中用于 Goroutine 间通信的类型安全的通道。它是 CSP 模型的物理载体——既负责传数据,也负责同步。

1. 核心特性

  • 类型安全:声明时锁定类型,如 chan int 只能传 int
  • 同步 / 异步:无缓冲 = 同步;有缓冲 = 半异步 (容量内异步,满了同步)
  • 阻塞:满了 send 阻塞 / 空了 recv 阻塞——Goroutine 会被挂起,不占 CPU
  • 引用类型:chan 底层是一个堆上的 hchan 结构体,变量本身是指针

2. 基础语法

// 1. 声明 (零值是 nil,nil channel 不可用)
var ch chan int

// 2. 创建无缓冲 channel
ch = make(chan int)
// 等价
ch := make(chan int)

// 3. 创建有缓冲 channel (容量 10)
buf := make(chan int, 10)

// 4. 发送
ch <- 42

// 5. 接收
v := <-ch

// 6. 接收 + 检测是否关闭
v, ok := <-ch     // ok=false 表示 channel 已关闭且无剩余数据

// 7. 关闭
close(ch)

// 8. for range 持续接收,直到 close
for v := range ch { /* ... */ }

类型安全泛型 BlockingQueue<T>编译期类型 chan T

Java 对照示例 
BlockingQueue<Integer> q = new ArrayBlockingQueue<>(10);

new Thread(() -> {
    try { q.put(42); } catch (InterruptedException e) { /* ... */ }
}).start();

int v = q.take();  // 阻塞接收
Java 需要处理 InterruptedException,Go 完全没有这个负担——channel 阻塞是协作式的,不会抛异常。

5. 最小可运行示例

package main

import "fmt"

func main() {
    ch := make(chan string)

    go func() {
        ch <- "Hello from Channel!"   // 发送 (阻塞,等接收)
    }()

    msg := <-ch                       // 接收
    fmt.Println("收到:", msg)

    // 类型安全:下面这行编译就报错
    // ch <- 42  // ❌ cannot use 42 (type int) as type string
}

6. nil Channel 行为(冷知识)

未初始化的 channel 是 nil,对它的所有操作都会永久阻塞(不会 panic):

操作nil channel已关闭 channel
发送 ch <- v永久阻塞panic
接收 <-ch永久阻塞立即返回零值,ok=false
close(ch)panicpanic (重复关闭)
为什么 nil channel 不 panic? 因为 select 语句里把某个 case 的 channel 设为 nil 是禁用这个 case的常用技巧——下一课 (Select) 会用到。

7. 常见坑点

坑点 1:向已关闭 channel 发送 会立即 panic: send on closed channel。规则:谁创建谁负责关闭,且只有发送方应该关闭。
坑点 2:接收时不检测 ok v := <-ch 不能区分「收到零值」和「channel 已关闭」。需要时用 v, ok := <-ch。
坑点 3:忘记关闭导致 for range 死锁 for v := range ch 会一直读到 close。如果生产者忘记 close,for range 永远阻塞。

📝 练习题

  1. 实现「ping-pong」:两个 goroutine 用一个 channel 来回发送数字,主 goroutine 等到第 10 轮后停下。
  2. 声明一个 nil channel,尝试发送和接收,观察程序如何卡死 (用 go run -race 看 deadlock 报错)。
  3. 写一个返回 channel 的工厂函数 func numbers() <-chan int,内部启动 goroutine 持续发数字,然后 close。
