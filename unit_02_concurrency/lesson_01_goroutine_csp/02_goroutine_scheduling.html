1.2 Goroutine 调度与栈扩容

上一节学了 Goroutine 是什么,这一节我们打开 Go runtime 的发动机舱:看看几千个 Goroutine 是如何被复用到少量 OS 线程上的——这就是 G-M-P 调度模型。

1. G-M-P 三个核心角色

  • G (Goroutine):一个 Goroutine,包含执行栈、PC、状态等
  • M (Machine):一个 OS 线程 (Machine 意为「机器执行单元」)
  • P (Processor):逻辑处理器,持有一个本地 G 队列。M 必须先拿到 P,才能执行 G

P 的数量默认等于 CPU 核心数,可通过 GOMAXPROCS 调整。

3. 调度流程关键点

  • P 默认数量 = CPU 核心数 (可用 runtime.GOMAXPROCS(n) 修改)
  • 每个 P 持有一个本地 G 队列 (容量 256),减少全局锁竞争
  • M 必须绑定 P 才能执行 G——只有 P 是「执行许可证」
  • 系统调用阻塞:当 G 陷入 syscall (如读文件),M 会被「卡住」,Go runtime 会把 P 从 M 上摘下来,交给另一个空闲 M 继续跑其他 G
  • Work Stealing:某个 P 的本地队列空了,会先从全局队列拿,再从其他 P 偷一半 G

4. Goroutine 的动态栈

Java Thread 启动时就要分配 1-2MB 固定栈;Goroutine 不一样——它从 2KB 开始,按需扩容:

Java 对照 Java Thread 栈大小由 -Xss 决定,通常 1MB 起;1000 个 Java Thread 直接吃掉 1GB 内存。 而 1000 个 Goroutine 起步只占 2MB——这就是 Goroutine 能轻松上万的物理原因。

5. 观察实战

package main

import (
    "fmt"
    "runtime"
    "sync"
    "time"
)

func main() {
    fmt.Println("GOMAXPROCS:", runtime.GOMAXPROCS(0))
    fmt.Println("初始 Goroutine 数:", runtime.NumGoroutine())  // 1

    var wg sync.WaitGroup
    for i := 0; i < 10000; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            time.Sleep(1 * time.Millisecond)
        }(i)
    }

    fmt.Println("峰值 Goroutine 数:", runtime.NumGoroutine())  // ~10001
    wg.Wait()
    fmt.Println("结束后 Goroutine 数:", runtime.NumGoroutine())  // 1
}

6. 生产坑点

坑点 1:Goroutine 泄露 典型场景:Channel 永远阻塞、忘记 cancel Context、循环依赖。 检测:pprof 的 goroutine profile,或周期性打印 runtime.NumGoroutine()。 解决:每个 goroutine 必须有明确退出路径 (close channel / context.Done() / 完成 return)。
坑点 2:滥用 GOMAXPROCS 默认值 (CPU 核心数) 几乎是最优解。容器化部署时注意:Go < 1.5 在 cgroup 受限的容器里看到的核数是宿主机的; 用 uber-go/automaxprocs 库自动读 cgroup CPU 配额——这是生产环境必装。
坑点 3:深递归导致频繁栈扩容 栈扩容是 2KB → 4KB → 8KB → ... 翻倍涨,每次涨都要 memmove 整块栈。 深度递归 (如解析嵌套 JSON) 会频繁触发,影响性能。 用 GODEBUG=gctrace=1 观察,或把递归改成迭代/堆分配大对象。

📝 练习题

  1. 创建不同数量的 Goroutine (100, 1000, 10000),用 runtime.ReadMemStats() 测量内存占用差异。
  2. 修改 GOMAXPROCS 为 1, 2, 4, 8,跑 CPU 密集型任务,记录耗时变化。再对比 IO 密集型任务的差异。
  3. 写一个会泄露 goroutine 的程序 (channel 永久阻塞),用 net/http/pprof 在浏览器查看泄露点。
