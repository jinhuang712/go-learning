1.4 WaitGroup 基础用法

sync.WaitGroup 是 sync 包提供的同步原语,用来等待一组 goroutine 完成。它本质上是一个原子计数器加 + 阻塞等待器。

1. 三个核心方法

方法作用说明
Add(delta int)计数器 += deltadelta 可以是负数,但必须在启动 goroutine 前调用
Done()计数器 -= 1等价于 Add(-1),通常用 defer wg.Done()
Wait()阻塞直到计数器归 0可以被多个 goroutine 同时 Wait,都会被唤醒

3. Java CountDownLatch 对照

特性Java CountDownLatchGo sync.WaitGroup
初始计数构造函数固定 new CountDownLatch(3)动态 wg.Add(n),可多次调用
计数方向只能减 (countDown())可正可负 (Add(±n) / Done())
等待方法await() / await(timeout)Wait() 无超时 (需配合 context)
重用不可重用归零后可再次 Add 重用
越界计数减到负会抛 IllegalStateException计数减到负会 panic
Java 对照 
CountDownLatch latch = new CountDownLatch(3);

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        try { /* 做事 */ }
        finally { latch.countDown(); }  // 等价于 wg.Done()
    }).start();
}
latch.await();  // 等价于 wg.Wait()
WaitGroup 比 CountDownLatch 更灵活:可以动态增减计数、可以复用。但没有超时,要超时必须配合 Context。

4. 标准用法

func main() {
    var wg sync.WaitGroup
    jobs := []string{"job1", "job2", "job3"}

    for _, job := range jobs {
        wg.Add(1)         // ✅ 启动 goroutine 之前 Add
        go func(j string) {
            defer wg.Done()  // ✅ 用 defer 确保即使 panic 也 Done
            fmt.Println("Processing", j)
        }(job)
    }

    fmt.Println("Waiting...")
    wg.Wait()  // 阻塞直到所有 worker Done
    fmt.Println("All done!")
}

5. 4 大坑点

坑点 1:在 goroutine 内部 Add 
// ❌ 错!Wait 可能在 Add 之前就执行,直接返回
for i := 0; i < 3; i++ {
    go func() {
        wg.Add(1)        // Wait 可能已经 return 了
        defer wg.Done()
        fmt.Println("worker")
    }()
}
wg.Wait()  // 可能立即返回 (计数器还是 0)
规则:Add 必须在启动 goroutine 之前,在调用 Wait 之前。
坑点 2:忘记 Done 
// ❌ 错!Wait 永远阻塞,造成 goroutine + 主 goroutine 泄露
wg.Add(1)
go func() {
    fmt.Println("worker")
    // 忘了 wg.Done()
}()
wg.Wait()  // 永远阻塞
规则:总是 defer wg.Done() 放在 goroutine 第一行——确保 panic 也能减计数。
坑点 3:WaitGroup 复制 (最隐蔽) 
// ❌ 错!worker 函数参数是值拷贝,内部 Done 改的是副本
func worker(id int, wg sync.WaitGroup) {  // 值传递!
    defer wg.Done()
    fmt.Println("worker", id)
}

func main() {
    var wg sync.WaitGroup
    wg.Add(3)
    for i := 0; i < 3; i++ {
        go worker(i, wg)  // wg 被拷贝,Done 改的是副本!
    }
    wg.Wait()  // 主 wg 计数器永远是 3,死锁
}
规则:WaitGroup 必须传指针 *sync.WaitGroup,或者闭包捕获外层变量。 go vet 会自动检测 WaitGroup 拷贝。
坑点 4:Add 负数 / Done 多了 计数器变成负数会立即 panic:sync: negative WaitGroup counter。
规则:确保 Done 调用次数 = Add 的总和。

6. 进阶模式:WaitGroup + 收集结果

WaitGroup 只能等完成,不能传递结果。要拿结果必须组合 channel:

func main() {
    var wg sync.WaitGroup
    results := make(chan int, 5)  // 缓冲 channel 收结果

    for i := 1; i <= 5; i++ {
        wg.Add(1)
        go func(n int) {
            defer wg.Done()
            results <- n * n  // 把结果写进 channel
        }(i)
    }

    // 关键模式:用单独的 goroutine 等 wg + 关闭 channel
    go func() {
        wg.Wait()
        close(results)  // 通知接收方:没数据了
    }()

    // 主 goroutine 收结果
    for r := range results {
        fmt.Println(r)
    }
}
这个模式很重要 wg.Wait() 单独放到一个 goroutine 里,然后 close(results)——这样主 goroutine 用 for range 收结果,通道关闭就自然退出。Go 标准 fan-out / fan-in 模式的核心写法。
