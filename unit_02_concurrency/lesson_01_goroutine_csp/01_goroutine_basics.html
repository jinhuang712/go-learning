1.1 Goroutine 基础入门

Goroutine 是 Go 实现并发的核心机制。它是用户态的轻量级执行单元,由 Go 运行时 (Runtime) 调度,而不是直接由操作系统调度。

1. 核心特性

  • 轻量级:初始栈仅 2KB,可动态扩容到 GB 级
  • 用户态调度:由 Go runtime 的 G-M-P 调度器管理 (下一节会详细讲)
  • 低开销:创建和切换成本极低,相比 OS 线程小 1000 倍
  • 轻松百万并发:单机轻松创建数十万 Goroutine,而 Java Thread 通常上限在几千个

Java 对照 Java 的 new Thread(() -> {...}).start() 背后是一次系统调用,需要内核分配栈空间; 而 Go 的 go func(){...}() 只是把一个 G 结构体挂到 P 的本地队列,纯用户态操作,基本就是一次内存分配。

4. go 关键字语法

启动一个 Goroutine 极其简洁——只需要 go 加函数调用:

// Java: 创建一个线程
new Thread(() -> {
    System.out.println("Hello from Java Thread");
}).start();
// Go: 创建一个 Goroutine
go func() {
    fmt.Println("Hello from Goroutine")
}()

5. 坑点 1:main 提前退出

这是 Go 新手第一个会遇到的坑——main 函数本身也是一个 Goroutine,它叫「主 Goroutine」。一旦 main 退出,整个程序就退出,其他 Goroutine 不管是否完成都会被强制终止。

// 错误:main 立即退出,sayHello 还没机会运行
func main() {
    go sayHello()  // 启动 Goroutine
    // main 立刻结束 → 整个程序退出 → sayHello 没机会打印
}

func sayHello() {
    fmt.Println("Hello")
}
// 临时正确写法:用 time.Sleep 撑住 main (只用于学习演示)
func main() {
    go sayHello()
    go sayHi()
    time.Sleep(100 * time.Millisecond)  // 生产环境绝对不要这么写!
}
坑点 time.Sleep 同步只是临时演示。真实项目里必须用 sync.WaitGroup 或 channel 同步——下面 1.4 节会讲。

6. 坑点 2:Goroutine 泄露

因为 Goroutine 太轻,很容易写到一半忘记终止条件,导致它永远阻塞。这种泄露在生产环境表现为:内存只增不降,runtime.NumGoroutine() 数字不停涨,直到 OOM。

7. 坑点 3:Goroutine ID 没有公开 API

Go 故意不暴露 Goroutine ID。和 Java Thread.currentThread().getId() 不同,Go 认为「goroutine 应该是匿名的」,这样能避免开发者把状态绑定到 ID 上 (反模式)。

  • 需要追踪请求时,用 context.Context 传递 trace ID
  • 不要用第三方包 (如 petermattis/goid) 反射拿 ID——会随 Go 版本变化而崩

8. 完整可运行示例

package main

import (
    "fmt"
    "runtime"
    "time"
)

func main() {
    fmt.Println("开始前 Goroutine 数:", runtime.NumGoroutine())  // 1 (main)

    for i := 0; i < 5; i++ {
        go func(id int) {
            fmt.Printf("Goroutine %d 工作中\n", id)
        }(i)
    }

    fmt.Println("启动后 Goroutine 数:", runtime.NumGoroutine())  // 1 ~ 6 之间
    time.Sleep(100 * time.Millisecond)
    fmt.Println("结束前 Goroutine 数:", runtime.NumGoroutine())  // 1
}
闭包变量陷阱预告 上面循环里我们写的是 go func(id int){...}(i),显式把 i 作为参数传入。 如果写成 go func(){ fmt.Println(i) }(),所有 goroutine 会共享同一个 i,输出几乎全是 5。 这个坑点在 Go 1.22 之前是经典面试题,Go 1.22+ 已修复 (每轮循环 i 是新变量)。

📝 练习题

  1. 启动 5 个 Goroutine,每个打印 1-5,观察输出顺序为什么不固定。
  2. 对比「直接调用 1000 次函数」和「启动 1000 个 Goroutine 调用」的耗时差异,理解并发执行的意义。
  3. 用 runtime.NumGoroutine() 写一个监控函数,周期性打印当前 goroutine 数量。
