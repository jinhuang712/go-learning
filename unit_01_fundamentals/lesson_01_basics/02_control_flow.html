1.2 控制流与 Defer

Go 的控制流比 Java 更精简,去掉了冗余括号,并增强了部分功能。

2.1 只有 for 循环

Go 没有 while 或 do-while,一切皆 for。

// 1. 标准循环
for i := 0; i < 3; i++ { /* ... */ }

// 2. while 替代
n := 0
for n < 5 {
    n++
}

// 3. 无限循环
for {
    if needStop {
        break
    }
}

2.2 if/else 带初始化语句

Go 的 if 允许在条件判断前先执行一条简短初始化语句,两部分用分号隔开。

基本语法:if 初始化语句; 条件表达式 { ... }

Java 痛点 在 Java 中,如果要调用方法、判断结果、并只在 if 块内使用结果,你通常这么写: 
// res 的作用域污染整个外部方法
Result res = doSomething();
if (res != null) {
    System.out.println(res);
}
// 这里依然可以访问 res
Go 的优雅解法 通过带初始化的 if,把变量作用域严格限制在 if/else 块内部。 
if err := doSomething(); err != nil {
    fmt.Println("出错了:", err)
    return err
}
// 离开 if 块后,err 变量已销毁,外部无法访问

2.3 switch (默认不穿透)

与 Java 最大的不同:Go 的 switch 默认不会穿透 (fallthrough),匹配到一个 case 执行完后自动退出,不需要写 break。

switch day {
case "Monday", "Tuesday": // 可以匹配多个值
    fmt.Println("Workday")
case "Sunday":
    fmt.Println("Weekend")
default:
    fmt.Println("Unknown")
}

2.4 defer 延迟执行

defer 是 Go 的一大特色,用于确保函数在退出前一定执行某些清理操作(类似 Java finally,但写法更就地、更优雅)。

  • 执行时机:当前函数 return 之前。
  • 常见场景:关闭文件、释放锁、关闭 DB 连接。
  • 多个 defer:按 LIFO(后进先出栈)顺序执行。
func processFile() {
    file := openFile()
    defer file.Close() // 无论后面发生什么,函数退出时都会执行

    // 业务逻辑...
}

Note over Func: 主体业务逻辑执行 Func-->>Func: return Stack-->>Func: pop B → 执行 Stack-->>Func: pop A → 执行 Func-->>Caller: 函数真正退出
图 · defer 的 LIFO 栈式执行时序
坑点 defer f(arg) 的参数在 defer 注册时立即求值,但函数体延迟到 return 前才跑。 defer func() { ... }() 闭包的写法则可以捕获最新状态。

📝 练习题

  1. 用 for 写一个不带任何条件的无限事件循环,通过 break 在收到 stop 信号时退出。
  2. 写一个函数 readConfig():打开文件、读取内容、出错时使用 if err := ...; err != nil 的带初始化判断,并用 defer 关闭文件。
