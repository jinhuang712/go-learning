1.5 深浅拷贝 (Copy vs Clone) 的底层逻辑

Java 对照 在 Java 中,赋值一个对象给另一个变量,默认只是传递引用(浅拷贝)。 要完整复制,必须实现 Cloneable 接口并重写 clone()(深拷贝)。

但在 Go 中,情况完全不同。核心法则只有一条:

Go 一切皆值传递 Go 中所有赋值 (=)、函数参数传递,全是「值传递」(浅拷贝)。 这听起来简单,但碰到复合类型很容易出错。下面分类讨论。

5.1 基础类型与纯值结构体(真正的深拷贝)

对于 int / float / bool 和不含指针的 struct,赋值会完整复制内存,修改新变量绝对不影响老变量。

type Point struct { X, Y int }
p1 := Point{1, 2}
p2 := p1 // 完整内存拷贝
p2.X = 99
// p1.X 依然是 1

5.2 引用类型的赋值(浅拷贝陷阱)

Go 中的引用类型主要有 3 种:Slice / Map / Channel。把 Slice 赋值给另一个变量时,Go 依然是值传递,但传递的是 Slice 的3 字段结构体(Pointer, len, cap)。

因为复制的 Pointer 依然指向同一块底层数组,这就产生了浅拷贝效果:

s1 := []int{1, 2, 3}
s2 := s1 // 只拷贝了 slice 结构体(24字节),底层数组没拷贝!

s2[0] = 999
// s1[0] 也变成 999!共享底层数组
图 · Slice 浅拷贝:两个 header 各自一份,底层数组只有一份

5.3 结构体内部包含引用类型(半深半浅)

这是业务开发中最容易出 Bug 的地方。如果你的结构体里包含 Slice 或 Map:

type User struct {
    Name string
    Tags []string // 切片 (引用类型)
}

u1 := User{Name: "Alice", Tags: []string{"admin", "vip"}}
u2 := u1 // 拷贝整个结构体

此时:

  • u2.Name = "Bob" — 不会影响 u1 (string 是不可变值类型)
  • u2.Tags[0] = "guest" — 会影响 u1!Tags 切片浅拷贝,共享底层数组

5.4 在 Go 中实现真正的 Deep Copy

Go 标准库没有通用深拷贝函数(因为反射深拷贝性能极差)。两种方案:

方案 1:手动逐字段赋值(推荐)

func (u *User) Clone() *User {
    // 1. 拷贝值类型字段
    clone := &User{Name: u.Name}
    // 2. 深拷贝切片字段
    if u.Tags != nil {
        clone.Tags = make([]string, len(u.Tags))
        copy(clone.Tags, u.Tags) // 内置 copy 函数
    }
    return clone
}

方案 2:JSON 序列化反序列化(最懒,性能极差)

把对象 json.Marshal 变成字节流,再 json.Unmarshal 到新对象。在性能苛刻的微服务中,强烈不推荐这种做法。

📝 练习题

  2. 用 benchmark 对比 Clone() 与 JSON 深拷贝 的性能,记录差距数量级。
