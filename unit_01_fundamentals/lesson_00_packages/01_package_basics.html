0.1 Go Package 基础

Java 对照 Java 中包名是反向域名(如 com.example.utils),且必须与文件系统目录结构一一对应。包是逻辑的、由 package 声明决定;目录是物理的、由编译器/JVM 强制对齐。

5.1 什么是 Go Package

Package 是 Go 代码的基本组织单元,用于将相关的 Go 源代码组织在一起,并通过它来界定可见性、依赖与命名空间。

3 条核心规则
  • 一个目录下的所有 .go 文件必须声明属于同一个 package
  • package 名通常是目录名的最后一段(但不要求强制相同)
  • 同一个 package 下的文件可以互相访问未导出(小写开头)的标识符

package 声明

每个 .go 文件的第一行必须是 package 声明:

package mypackage

目录结构与 Package 的关系

Go 使用文件系统目录来组织 package,而不是像 Java 那样在文件中声明完整的包路径。

example.com/
├── go.mod
├── main.go
└── utils/
    ├── string.go  // package utils
    └── math.go    // package utils

💻 可运行代码示例

下面演示一个最基本的 Package 组织。greeting/ 目录下两个文件同属于 greeting 包,可以互相访问私有标识符。

// 目录结构:
// demo/
// ├── go.mod
// ├── main.go
// └── greeting/
//     ├── hello.go
//     └── hi.go

// greeting/hello.go
package greeting

import "fmt"

func Hello() {
    fmt.Println("Hello!")
}

// greeting/hi.go
package greeting  // 同一个目录,必须是同一个 package

import "fmt"

func Hi() {
    fmt.Println("Hi!")
}

// main.go
package main

import (
    "demo/greeting"
)

func main() {
    greeting.Hello()
    greeting.Hi()
}

⚠️ 生产环境坑点

坑点 1 · 同一个目录下不同的 package 声明 
// 错误写法 - 同一个目录下不能有不同的 package
// file1.go
package utils

// file2.go (同一个目录)
package helpers // 编译错误!

// 正确写法 - 必须同一个 package
// file2.go
package utils
坑点 2 · 循环 import Go 不允许循环导入 (与 Java 不同)。如果 a.go 导入 b,b.go 又导入 a,直接编译失败。
解决方法: 重构代码,提取公共部分到第三个 package。
坑点 3 · package 名和目录名不一致 
// 虽然允许,但不推荐
// 目录: stringutils/
// 文件: stringutils/str.go
package str // package 名与目录名不一致

// 推荐做法
package stringutils // package 名与目录名一致
