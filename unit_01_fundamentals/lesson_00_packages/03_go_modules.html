0.3 Go Module 系统

Java 对照 Java 用 pom.xml(Maven)或 build.gradle(Gradle)管理依赖,依赖以 groupId:artifactId:version 三元组定位,本地缓存在 ~/.m2/repository。 Go 用一个极简的 go.mod 文件,依赖以 module-path@version 标识,缓存在 $GOPATH/pkg/mod。

什么是 Go Module

Go Module 是 Go 1.11+ 引入的官方依赖管理系统,取代了早期的 GOPATH 模式,用于管理 Go 项目的依赖。一个 module 是一个独立版本化、可发布的代码集合。

go.mod 文件

每个 Go Module 根目录下都有一个 go.mod 文件:

module example.com/myproject

go 1.21

require (
    github.com/gin-gonic/gin v1.9.0
)

Module 路径

Module 路径是模块的唯一标识,通常对齐代码仓库地址:

  • github.com/username/project
  • example.com/myproject

常用命令

命令说明
go mod init <module-path>初始化新 module
go mod tidy添加缺失的依赖,删除未使用的依赖
go get <package>添加或更新依赖
go mod download下载依赖到本地缓存
go list -m all列出所有依赖

💻 可运行代码示例

1) 初始化和使用 Go Module

# 初始化新 module
go mod init example.com/myproject

# 添加依赖
go get github.com/gin-gonic/gin

# 整理依赖
go mod tidy

# 查看所有依赖
go list -m all

2) 在代码中使用

// main.go
package main

import "github.com/gin-gonic/gin"

func main() {
    r := gin.Default()
    r.GET("/", func(c *gin.Context) {
        c.JSON(200, gin.H{
            "message": "hello world",
        })
    })
    r.Run()
}
go.sum 的作用 go.sum 是依赖内容校验和文件,保证拉取的依赖在版本一致的情况下,字节级别也一致。 类似 package-lock.json 或 gradle.lockfile 的角色。务必提交到 git。

⚠️ 生产环境坑点

坑点 1 · 是否提交 vendor 目录到 Git 
# 可选 - 将依赖整体落盘到仓库
go mod vendor

# 是否提交 vendor/ 到 Git?
# - 优点:构建时不需要网络
# - 缺点:仓库体积变大
# - 建议:CI/CD 环境不提交,离线构建场景才考虑提交
坑点 2 · 直接手动编辑 go.mod 
# 不推荐 - 手动编辑 go.mod 容易出错

# 推荐 - 使用 go 命令管理
go get github.com/example/pkg@v1.2.3
go mod tidy
坑点 3 · 忽略 go.sum .gitignore 中绝不要忽略 go.sum。它是依赖的校验和,保证依赖不被篡改、可重复构建。

  • 成功添加依赖

  • go.mod 和 go.sum 文件正确
