0.2 Import 机制

Java 对照 Java 中 import java.util.* 是通配符导入,导入的是整个包(或单个类)。 Go 永远只能导入整个包,不存在「只导入某个类型/函数」的语法,也不存在通配符导入。

import 语法

Go 使用 import 关键字导入其他 package:

import "fmt"
import "example.com/utils"

批量导入(推荐写法):

import (
    "fmt"
    "example.com/utils"
)

Import 路径

Import 路径是基于 module 路径的(由 go.mod 中的 module 行决定),而不是文件系统的相对路径。这是和 Java 最大的差别之一。

导入的 4 种形态

方式语法说明
默认导入import "fmt"使用 fmt.Println()
命名导入import f "fmt"使用 f.Println()
点导入import . "fmt"直接 Println()(不推荐)
下划线导入import _ "example.com/driver"只执行 init,不使用包

💻 可运行代码示例 · 4 种导入方式合体

package main

import (
    "fmt"
    m "math"           // 命名导入
    . "strings"        // 点导入 (不推荐在生产环境使用)
    _ "net/http/pprof" // 下划线导入,只触发 init
)

func main() {
    fmt.Println("Pi:", m.Pi)
    fmt.Println("Upper:", ToUpper("hello")) // 点导入后可直接使用
}
下划线导入的典型场景
  • 数据库驱动注册: import _ "github.com/go-sql-driver/mysql" 触发 sql.Register("mysql", ...)
  • HTTP pprof 注册: import _ "net/http/pprof" 自动注册 /debug/pprof/* 路由
  • image 解码器注册: import _ "image/png" 让 image.Decode 支持 PNG

⚠️ 生产环境坑点

坑点 1 · 滥用点导入 
// 不推荐 - 点导入会导致命名空间污染
import . "fmt"
import . "strings"

func main() {
    Println("Hello") // Println 是 fmt 还是 strings 的?
}

// 推荐做法
import "fmt"

func main() {
    fmt.Println("Hello")
}
坑点 2 · 循环导入 Go 不允许循环导入。a.go 导入 b,b.go 导入 a → 编译失败。
解决方法: 提取公共接口或类型到第三个包(典型做法是引入 internal/types 或顶层 domain 层)。
坑点 3 · 未使用的导入 
// 错误 - Go 不允许未使用的导入
import (
    "fmt"
    "unused" // 编译错误!
)

// 解决方法 1:删除未使用的导入
// 解决方法 2:使用下划线导入(仅当确实需要触发 init)
import _ "unused"
