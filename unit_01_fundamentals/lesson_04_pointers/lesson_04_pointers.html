Lesson 4 · 指针与值语义 (Pointers & Value Semantics)

本课程专门讲解 Go 语言中的指针。这是 Java 开发者转向 Go 时最需要建立的核心心智模型之一。Java 里看似透明的「对象引用」,在 Go 里被拆成了「值」和「指针」两条清晰的路径——你必须主动选择走哪条。

Java 对照 Java 程序员从不会显式写 & 或 *:对象都是隐式引用,基本类型都是值。但 JVM 为你做了选择。 Go 把这个选择权交还给程序员,代价是你必须搞懂 T 和 *T 在赋值、传参、方法接收者下的语义差异。

1. * 和 & 到底是什么意思?

  • & (取址符):获取一个变量在内存中的地址。
  • * (指针类型 / 解引用):
    • 放在类型前面(如 *int, *User):表示这是一个指针类型,即「用来存放内存地址的变量」。
    • 放在变量前面(如 *p):表示解引用 (Dereference),即顺着这个内存地址,去读取或修改里面存放的实际数据。
x := 42
p := &x          // p 是 *int 类型,存的是 x 的地址
fmt.Println(*p) // 解引用 → 输出 42
*p = 100        // 通过地址改 x
fmt.Println(x)  // 输出 100

2. Stack vs Heap:指针指向哪里?

Go 的逃逸分析 (Escape Analysis) 决定一个变量被分配在栈上还是堆上。简单原则:如果指针逃出了创建它的函数作用域,就会被分配到堆上(由 GC 回收)。

3. Go 的「值传递」 vs Java 的「引用」

这是整个 Lesson 的核心心智模型。下面是 Java 与 Go 的并列代码对比:

Java 写法

class User {
    public String name;
    public int age;
}

public void updateUser(User user) {
    user.name = "Alice"; // 修改的是原对象的属性
    user = new User();   // 只是把局部变量 user 指向了新对象,不影响外部
}

public static void main(String[] args) {
    User u = new User();
    u.name = "Bob";
    updateUser(u);
    System.out.println(u.name); // 输出 "Alice",原对象被修改了
}

Go 写法

type User struct {
    Name string
    Age  int
}

// 传值:拷贝整个结构体
func updateUserByValue(u User) {
    u.Name = "Alice" // 修改的是副本,不影响外部
}

// 传指针:拷贝内存地址
func updateUserByPointer(u *User) {
    u.Name = "Alice" // 通过地址修改原对象
}

func main() {
    u := User{Name: "Bob"}
    updateUserByValue(u)
    fmt.Println(u.Name) // 输出 "Bob",原对象没被修改

    updateUserByPointer(&u)
    fmt.Println(u.Name) // 输出 "Alice",原对象被修改
}
关键差异
  • Java:对象变量默认是「引用」(隐式的指针)。当你把一个对象传给方法时,传递的是引用的拷贝,方法内可以直接修改对象的属性。
  • Go:一切皆为值传递 (Pass by Value)。
    • 传 User(结构体):Go 把整个结构体的数据完整拷贝一份给函数。你在函数内修改它,完全不影响外部的原对象。
    • 传 *User(指针):Go 拷贝的是「内存地址」(通常就 8 个字节)。你在函数内通过这个地址去修改属性,就能真正修改到外部的原对象。

4. 为什么需要指针?

  1. 修改原变量:当你需要在函数或方法内部修改外部传入的变量状态时。
  2. 避免大对象拷贝(性能优化):当结构体非常大(包含几十个字段)时,传值会导致严重的内存拷贝开销,传指针只需拷贝 8 字节。
  3. 表达 null 语义:在 Go 中,值类型不能为 nil(比如 int 默认是 0,string 默认是 "")。如果你在 JSON 解析或数据库查询时,需要区分「没传这个字段」和「传了 0」,你就必须用指针 *int(因为指针可以为 nil)。

5. 常见坑 (Pitfalls)

空指针解引用 (Panic) 类似 Java 的 NullPointerException。如果你声明了一个指针但没有初始化,它的默认值是 nil。 此时直接写 *p = 10 会导致程序崩溃 (panic)。 必须先初始化(比如通过 &x 获取已有变量的地址,或者用 new(int) 分配内存)。 
var p *int      // p == nil
*p = 10         // runtime error: invalid memory address or nil pointer dereference

// 正确姿势 1
x := 0
p = &x
*p = 10         // OK

// 正确姿势 2
p = new(int)    // 分配一块零值 int,返回其地址
*p = 10         // OK
结构体指针的语法糖 在 C 语言中,结构体指针访问字段要写 (*p).Name 或 p->Name。 但在 Go 中,不管是值还是指针,都可以直接写 p.Name,Go 编译器会在底层自动帮你解引用。 
u := &User{Name: "Bob"}
// 下面两行完全等价
fmt.Println((*u).Name)
fmt.Println(u.Name)      // ✅ Go 自动 deref,推荐写法
